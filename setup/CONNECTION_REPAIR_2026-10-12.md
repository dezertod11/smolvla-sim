# Исправление среды VS Code, 12 октября 2026

## Причина и границы диагноза

В журналах были переподключения SSH/Dev Containers, задержки сервера редактора
и ошибка `listen ENOTSUP` для `/data/home/.gnupg/S.gpg-agent`.
Домашняя папка контейнера находилась на Windows bind mount. Отдельная проверка
подтвердила: Unix-сокет в `/data/home` не создавался, в Linux filesystem создавался.
Активный редактор также использовал обычный профиль без Docker-wrapper проекта.

Это подтверждённые проблемы настройки, но не доказательство единственной причины
всех прошлых зависаний. Один обрыв SSH совпал с выходом ноутбука из сна.
При диагностике сеть работала: 20 ping без потерь, средняя задержка 109 мс;
Tailscale использовал прямое соединение. Keepalive уже был настроен.

## Что изменено

- `/data/home` теперь отдельный постоянный Linux-том `smolvla-sim-home`.
  Путь HOME сохранён, поэтому пути настроек, расширений и истории не изменились.
  Сам том хранится внутри Docker Desktop, чей диск расположен на D:.
- Том объявлен external, чтобы `docker compose down -v` его не удалял.
  На ПК-1 он подготовлен, корень имеет владельца 1000:1000 и режим 700.
- Windows-папка `D:\Robotics\smolvla-sim\home` оставлена без удаления как
  резервная копия состояния до переноса. Изменения нового HOME в неё не попадают.
- `/workspace`, модели, датасеты и результаты в `/data` сохранены на прежних местах.
- `Open-PC1.ps1` восстанавливает `dev.containers.dockerPath` в специальном профиле,
  сохраняет другие предпочтения и резервную копию settings.json, исключает
  Docker-wrapper из Settings Sync. `-PrepareOnly` проверяет/готовит профиль без
  открытия окна; `-Container` открывает сразу контейнер.
- `Open-PC1.cmd` использует `-Container`: ежедневный запуск требует одной команды
  после запуска Docker Desktop на ПК-1.

## Резервные копии и восстановление

На ПК-1: `.runtime/connection-repair-20261012/` — архив исходников до изменений,
прежний Compose, inspect контейнера, исходный Git status, контрольные суммы и
`home-verification.log`. Каталог закрыт правами 700; не публиковать его в Git.
На ноутбуке настройки сохранены в
`%LOCALAPPDATA%\SmolVLA-VSCode\settings-backups`.

Для отката после начала работы в новом HOME сначала сохраните его новые данные:
старая Windows-копия отражает только состояние до переноса. Затем в согласованное
окно остановки уберите вложенное монтирование `/data/home` и пересоздайте только
сервис `dev`. Сам Linux-том не удаляйте. Возвращение Windows HOME снова приведёт
к ограничению Unix-сокетов, поэтому это аварийный откат, не рекомендуемый режим.

Сон ноутбука по-прежнему может прерывать SSH. Длительные вычисления следует
запускать на ПК-1/H100 с сохранением процесса и логов. Постоянная сетевая
стабильность не гарантируется одним исправлением файловой системы.
