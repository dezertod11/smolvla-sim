## Разбор данных первого эксперимента — 6 октября 2026

В Dev Container ПК-1 проверены установленный LeRobot и небольшие публичные
метаданные Hugging Face. Установленный commit LeRobot совпадает с закреплённым
`8fff0fde7c79f23a93d845d1a50e985de01f8b8a`. Веса и демонстрации не скачивались,
GPU не использовалась, окружение не менялось, подключение к H100 не выполнялось.

Воспроизводимая проверка **в контейнере ПК-1, из `/workspace`**:

```bash
python scripts/inspect_libero_metadata.py --output configs/libero_object_episodes.json
```

Команда читает около 1 МБ метаданных и каталог размеров файлов через сеть.
Сырые метаданные остаются в памяти. JSON содержит список эпизодов, соответствие
задач, размеры файлов, ревизии и SHA256 прочитанных источников; это конфигурационный
манифест выбора данных, не сами демонстрации и не конфиг обучения.

- Датасет: LeRobot v3.0, Panda, 10 Гц, 40 задач, 1 693 эпизода, 273 465 кадров.
- Для первого эксперимента предложен только `libero_object`: все 10 целевых задач,
  454 эпизода, 66 984 кадра, от 42 до 50 демонстраций на задачу. Это концентрирует
  обучение на обязательном наборе оценки; обобщение на другие наборы не проверяется.
- Нужные эпизоды занимают 19 Parquet-файлов: **1 651 839 721 байт** (~1,65 ГБ).
  Полные файлы данных: **34 925 150 020 байт** (~34,9 ГБ). Изображения в этой ревизии
  встроены в Parquet (`dtype=image`). Это объём скачивания файлов, без весов,
  рабочих кэшей, checkpoints и результатов; место на H100 ещё не проверено.
- Эпизоды выбраны по точному совпадению инструкций с установленным списком
  `libero_object`. Dataset `task_index` 20–29 не равен task ID 0–9 симулятора.
  Например, alphabet soup — dataset index 24, suite task 0 при `task_order_index=0`.
- Камеры датасета: `observation.images.image` и `observation.images.image2`,
  RGB 256×256. В обёртке LIBERO это внешняя камера и камера на запястье.
  Будущий `rename_map`: `image → camera1`, `image2 → camera2`
  (с полным префиксом `observation.images.` у всех ключей).
- Состояние имеет 8 компонент, действие — 7. Базовый checkpoint описывает 6/6
  и три камеры. В этой версии `make_policy` обновляет output features по датасету,
  но сохраняет непустые input features базовой модели. Поэтому в следующем шаге
  нужно явно задать состояние `[8]` и две камеры в конфиге, проверить processors
  и нормализацию. Одного переименования камер недостаточно для точного конфига.
- По исходникам, `train_expert_only=true` замораживает VLM целиком;
  обучаются action expert, проекции действий/времени и, при
  `train_state_proj=true`, проекция состояния. Реальные числа обучаемых параметров
  и dtype ещё не измерены: модель не загружалась.
- Выбор `dataset.episodes` ограничивает примеры обучения, но загруженные
  `meta.stats` остаются статистиками датасета. Выбор статистик нормализации
  нужно явно зафиксировать при подготовке эксперимента.

Проверки: скрипт успешно прочитал закреплённые метаданные, проверил число
эпизодов/кадров, уникальность индексов и наличие всех 10 задач; Ruff —

## Конфиг первого обучения — 12 октября 2026

Подготовлен `configs/train_libero_object.json` для штатного `lerobot-train`.
Незакоммиченные результаты анализа metadata и изменения настройки подключения
сохранены. Обучение, загрузка весов/демонстраций, изменение зависимостей,
перезапуск Docker и подключение к H100 на этом этапе не выполнялись.

- Данные: выбранные 454 эпизода, ревизия из `configs/artifacts.json`, без
  image augmentation и streaming. Это начальный эксперимент только на object.
- Входы заданы явно: две камеры CHW 3×256×256, состояние `[8]`; выход `[7]`.
  `rename_map` согласован с манифестом; отсутствующая третья камера исключена.
- `policy.pretrained_path=.runtime/models/base`; архитектурные параметры
  сохранены из закреплённого `smolvla_base`, включая 16 VLM layers, multiplier
  0.75 и padding `max_length`. Загрузку реальных весов ещё предстоит проверить.
- Нормализация: глобальные `meta/stats.json` закреплённого LIBERO, mean/std для
  состояния и действий; изображения — IDENTITY. Статистики включают все 40 задач,
  хотя градиенты будут вычисляться только по выбранным 10. Это явный выбор
  стандартного поведения LeRobot без изменения исходного датасета. Статистики
  базового робота заменяются processors override из штатного train-кода.
- Заморожена вся VLM (`train_expert_only=true`, `freeze_vision_encoder=true`).
  Обучаются action expert и проекции состояния/действий/времени. Так сохраняются
  зрительно-языковые признаки, а обучение сосредоточено на управлении Panda.
- Seed 42; batch size 16 — осторожная начальная величина до измерения памяти.
  30 000 шагов (~7,17 прохода по 66 984 кадрам при 16 примерах/шаг) —
  предварительный план, не обещание длительности или качества. AdamW 1e-4,
  warmup 1 000 шагов, cosine decay до 2.5e-6 к 30 000 шагам. Значения сохраняют
  штатный preset SmolVLA; их нужно пересмотреть после замера скорости/loss.
- `chunk_size=50`, `n_action_steps=10` явно заданы; обучение предсказывает
  полный чанк, а n_action_steps управляет исполнением при последующей оценке.
- W&B offline, логи каждые 50 шагов, checkpoint каждые 5 000 и на последнем
  шаге; публикация на Hub и W&B artifacts отключена. Встроенная оценка во время
  обучения отключена (`env=null`, `eval_freq=0`); success rate измеряется отдельно.
- Все пути данных/результатов относительны корню проекта H100 и находятся
  в `.runtime`. `resume=false`; повторному запуску нужен новый output_dir.
- Для BF16 AMP необходимо задать `ACCELERATE_MIXED_PRECISION=bf16` в будущей
  команде запуска через GPU guard. Конфиг `use_amp=true` сам по себе не определяет
  mixed precision у Accelerator. BF16 всей политики этим не доказан.

Итоговые проверки: Ruff — `All checks passed`, pytest — **10 passed**,

Ограничения: это проверка конфигурации и части processors, не реального batch,
